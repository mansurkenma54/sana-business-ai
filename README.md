# Sana Business AI

AI-помощник для малого и среднего бизнеса Тараза и Жамбылской области.
Трек: **AI for SME & Local Business — ИИ-решения для бизнеса**.

Репозиторий: [mansurkenma54/sana-business-ai](https://github.com/mansurkenma54/sana-business-ai) (приватный).

Готовый сайт: [sana-business-ai.vercel.app](https://sana-business-ai.vercel.app/).

Sana помогает предпринимателю найти процесс для улучшения, оценить возможный
денежный эффект и подготовить проверяемую задачу для внедрения. Цели продукта —
увеличение выручки, снижение затрат и сокращение ручной работы.

## Что умеет продукт

- **Анализ продаж из CSV:** выручка, себестоимость, валовая прибыль и маржа по
  продуктам и дням с фильтром дат. Файл обрабатывается в браузере без загрузки
  на сервер. Подсказки о низкой марже и зависимости от продукта вычисляются
  по явным правилам, без AI-модели.
- **Диагностика бизнеса:** отрасль, город, цель и описание проблемы превращаются
  в рекомендации, показатели для пилота, план действий и черновик задачи.
- **Калькулятор эффекта:** считает дополнительную валовую прибыль, экономию,
  стоимость инструментов, окупаемость и освобождённое время по вашим допущениям.
  Стоимость времени показана отдельно от денежного результата.
- **Проверка пилота:** сравнивает введённые значения «до», «цель» и «после».
  Достижение цели определяется по выбранному направлению показателя.
- **Библиотека сценариев:** кафе, торговля, красота, услуги, агробизнес и туризм.
  Любой пример можно адаптировать под свою ситуацию.
- **Сохранение и экспорт:** план сохраняется по кнопке в текущем браузере;
  JSON-отчёт содержит ввод, диагностику, расчёт, допущения и результаты пилота.
- **Внедрение с командой:** регистрация, AI-конструктор задачи, ручная публикация,
  каталог, предложения команд, выбор исполнителей, версии решения и приёмка бизнеса.

Анализ CSV, диагностика и расчёты доступны до входа. Аккаунт нужен для публикации и работы
с командой. Внутренняя роль `student` сохранена для совместимости API и обозначает
участника команды внедрения в интерфейсе.

AI не подтверждает финансовый результат: рекомендации — гипотезы для проверки,
числа калькулятора — сценарий по введённым предположениям. Демо явно обозначены;
реальных клиентов и доказанных результатов в стартовых данных нет.

## Локальный запуск

Нужны Python 3.11+ и Node.js 22.12+ (либо совместимая версия из `package-lock.json`).
Из корня репозитория в PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
npm ci
npm run build
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Откройте [локальный сайт](http://127.0.0.1:8000).
Если `.env` уже существует, сохраните его вместо повторного копирования.
На macOS/Linux используйте `python3`, `.venv/bin/python` и `cp .env.example .env`.

Для разработки фронтенда оставьте FastAPI на порту 8000 и в другом терминале
выполните `npm run dev`. Vite откроет адрес из вывода команды и перенаправит `/api`
на локальный FastAPI. Для production сервер отдаёт сборку из `app/static/`.

## AI и хранение

В `.env` можно задать `OPENAI_API_KEY`; модель задаётся `OPENAI_MODEL`.
Существующая интеграция также поддерживает AI Gateway. Секреты не входят
в репозиторий. Для полностью локальной работы без запросов к модели установите:

```dotenv
AI_MODE=fallback
SANA_LEGACY_MODE=0
```

При отсутствии доступного провайдера диагностика и конструктор используют
встроенные правила и явно показывают резервный режим. Состояние провайдера
доступно через `GET /api/health` без раскрытия секретов.

Рабочие задачи, аккаунты и команды по умолчанию хранятся в `.sana-data/` вне Git.
`SANA_DATA_DIR` меняет папку; `DATABASE_URL` включает существующий PostgreSQL-адаптер.
Файлы `data/` — синтетические фикстуры для проверок, а не наполнение живого каталога.
План бизнес-помощника сохраняется отдельно в `localStorage` только по кнопке:
он не синхронизируется с аккаунтом и другим устройством.

## Формат продаж CSV

Файл UTF-8 до 1 MiB, не более 10 000 строк продаж. Обязательные уникальные
столбцы: `date,product,quantity,price,cost`. Порядок можно менять.
`price` и `cost` — цена и себестоимость **одной единицы** в тенге, а не итог строки.
Даты — реальные календарные даты `YYYY-MM-DD`; числовые значения неотрицательные.
Поддерживаются запятая или точка с запятой как разделитель, кавычки и UTF-8 BOM.
Десятичная запятая удобна в CSV с разделителем `;`.

```csv
date,product,quantity,price,cost
2026-10-01,Демонстрационный кофе,2,1200,420
2026-10-01,Демонстрационный сэндвич,1,1800,1900
```

Выручка = сумма `quantity × price`, себестоимость = сумма `quantity × cost`,
валовая прибыль = разность, маржа = валовая прибыль / выручка × 100%.
При нулевой выручке маржа не определяется. Отрицательная прибыль сохраняется.
Это валовая прибыль по введённой себестоимости, без аренды, налогов и прочих
расходов, если они не включены в неё. Возвраты отрицательными строками не поддерживаются.
Демо, формат и скачивание отчёта доступны в разделе анализа продаж.

## Проверка сценария

1. Откройте анализ продаж, загрузите демо CSV, измените период и проверьте
   валовую прибыль и предупреждение об убыточном продукте. Затем откройте
   демонстрационный пример диагностики и проверьте пометку «ДЕМО».
2. Выполните диагностику и проверьте индикатор источника ответа.
3. В калькуляторе измените выручку, маржу, расходы и стоимость запуска;
   сравните результат с показанными формулами. Попробуйте нулевой и отрицательный эффект.
4. Заполните показатели пилота, сохраните план, восстановите его и скачайте JSON.
5. Перенесите черновик в конструктор, войдите как предприниматель, ответьте на
   вопросы и вручную подтвердите публикацию.
6. В отдельной сессии создайте аккаунт участника и команду, отправьте предложение.
   Бизнес выбирает команду; она отправляет результат, бизнес принимает его или
   возвращает с комментарием.

Автоматические проверки и сборка:

```powershell
.\.venv\Scripts\python.exe -m pytest -q
node --test tests/salesAnalytics.test.mjs
npm run build
```

Тесты используют временное хранилище и резервный AI. Успешный локальный прогон
не подтверждает доступность внешнего AI, production-хостинга или PostgreSQL.

## Границы версии

- Нет готовых подключений к кассам, CRM, WhatsApp или бухгалтерии: сценарий
  помогает сформировать пилот, интеграция выполняется отдельно.
- Калькулятор не проверяет достоверность ввода и не учитывает налоги, сезонность,
  риски спроса или дисконтирование. Не учитывайте одну экономию дважды.
- Показатели пилота вводятся вручную; приложение не доказывает причинную связь
  между внедрением и изменением показателя.
- Сохранённый в браузере план может быть потерян при очистке данных; для копии
  предусмотрен JSON-экспорт. Импорта JSON пока нет.
- Есть регистрация и сессии, но пока нет подтверждения email и восстановления пароля.
- Для реального размещения нужны HTTPS, постоянное хранилище, резервные копии,
  ограничения запросов и эксплуатационная проверка. Этот README не подтверждает
  наличие публичного deployment.
