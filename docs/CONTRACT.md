# Контракт данных и API Sana Business AI

Этот документ описывает переходы между React, FastAPI и хранилищем JSON/PostgreSQL. Рабочий режим использует аккаунты и серверные сессии: предприниматель публикует задачи и принимает результат, участник команды предлагает и выполняет решение. Диагностика бизнеса, шаблоны, каталог и отдельные карточки доступны без входа. Записывающие запросы требуют `X-Sana-Request: 1` и same-origin. Схема прежних личных токенов ниже сохранена для совместимости; она не отменяет права аккаунтов. Новая диагностика описана в разделе «Расширение: AI for SME & Local Business».

## Данные

### Карточка задачи

Поля, нужные для кейса:

| Поле | Смысл |
| --- | --- |
| `title` | Название |
| `context` | Что происходит сейчас |
| `need` | Что нужно изменить |
| `users` | Кто будет пользоваться результатом |
| `data_materials` | Данные, примеры, материалы |
| `constraints` | Сроки, технологии, доступы и другие границы |
| `expected_result` | Конкретный результат работы команды |
| `success_criteria` | Измеримые признаки успеха |
| `contact` | Контакт бизнеса |
| `interaction_format` | Формат консультаций и обратной связи |

Дополнительные поля: `id`, `industry`, `status`, `rating`, `created_at`. После явной публикации `status` равен `published`. До неё карточка существует в браузере как редактируемый черновик и не появляется в каталоге. Сервер пересчитывает `rating` при создании и изменении опубликованной задачи.

### Рейтинг

`rating` содержит `score` (0–100), `level`, `breakdown` (получено/максимум по каждому показателю), `missing` и `tips`. Поле засчитывается, если после обрезки пробелов по краям в нём не меньше 15 символов. Это правило приложения. Для показателей из двух полей одно заполненное поле даёт половину веса.

| Ключ | Поля | Вес |
| --- | --- | ---: |
| `context_need` | `context`, `need` | 20 |
| `data_materials` | `data_materials` | 20 |
| `expected_result` | `expected_result` | 15 |
| `success_criteria` | `success_criteria` | 15 |
| `constraints` | `constraints` | 10 |
| `users` | `users` | 10 |
| `business_link` | `contact`, `interaction_format` | 10 |

`level`: `draft` для 0–39, `working` для 40–69, `ready` для 70–89, `priority` для 90–100. Баллы рейтинга задачи не складываются с баллами фактического прогресса команды.

### Команда, предложение и результат этапа

`Team`: `id`, `name`, массивы строк `interests`, `skills`, `technologies`. Каждая команда создаётся через API и получает свой ключ. Синтетические команды из `data/` используются для проверок и не появляются в новом рабочем каталоге.

`Proposal`: `id`, `task_id`, `team_id`, `idea`, `plan`, `deadline`, `link`, `status`, `created_at`. Статус `new`, `accepted` или `rejected`. Число предложений не ограничено. Бизнес может принять несколько, одно или ни одного; система не назначает команду автоматически.

`Progress`: `id`, `proposal_id`, `task_id`, `team_id`, `result`, `evidence_link`, `status`, `points` и временные метки. Этап отправляет команда с принятым предложением. Статус `submitted`, `confirmed` или `rejected`; очки начисляются только после ручного подтверждения бизнеса. В MVP подтверждённый этап даёт 10 очков. Это проектное допущение: в PDF кейса количество очков не указано.

## Право на действие в прежнем режиме

Таблица описывает совместимость с токенами первоначальной версии. По умолчанию
`SANA_LEGACY_MODE=0`: публикация, изменение и действия команды требуют аккаунта
соответствующей роли. Политика аккаунтов описана ниже; переключение интерфейса
или наличие токена старой записи не даёт прав на новую аккаунтную запись.

| Действие | Ключ в заголовке |
| --- | --- |
| Создать задачу или команду | Не требуется; ответ содержит новый ключ |
| Изменить задачу, прочитать её предложения, принять или отклонить предложение, подтвердить этап | `X-Sana-Owner: <owner_token>` для этой задачи |
| Отправить предложение, увидеть предложения команды, отправить результат этапа | `X-Sana-Team: <team_token>` для этой команды |
| Открыть каталог, публичную карточку, список команд и рейтинг | Не требуется |

Нужно передавать ключ ровно той записи, от имени которой выполняется действие. Ключи не отправляются в тело карточки и не включаются в публичные ответы. Переключение роли в интерфейсе меняет экран, а не право доступа. Меню «Доступ» позволяет скопировать код задачи или команды на другое устройство; без сохранённой копии утерянный код восстановить нельзя.

## Формат ответа и AI

Основные API ответы обёрнуты в один формат:

```json
{"ok": true, "data": {}}
{"ok": false, "error": {"code": "invalid_input", "message": "Понятное описание ошибки"}}
```

Приложение возвращает ошибки в теле ответа; интерфейс проверяет `ok`. Исключение — `GET /api/health`: он возвращает статус, тип хранилища и безопасные поля `ai_mode`, `ai_reason`, `ai_model`, `ai_provider`, но никогда не возвращает API-ключ или OIDC-токен. Прямой `OPENAI_API_KEY` имеет приоритет; без него Vercel deployment использует AI Gateway через автоматически выдаваемый `VERCEL_OIDC_TOKEN`.

`POST /api/analyze` принимает `draft`, `industry`, `locale` (`ru`, `kk`, `en`) и возвращает не меньше трёх объектов `{"key":"data_materials","question":"...","suggestions":["...","...","..."]}`, список `missing` и `source` (`ai` или `fallback`). Три `suggestions` — редактируемые примеры ответа, а не факты пользователя. `POST /api/build-card` принимает исходный текст, ответы и язык; возвращает редактируемую `card` и `source`. Промпты находятся в `core/prompts.py`. Ответ модели проверяется: неправильный JSON или неподходящий набор вопросов ведёт к резервным вопросам; поле карточки принимается из AI только при точной цитате из введённого человеком текста. Неизвестные сведения остаются пустыми. При `AI_MODE=fallback` обращения к OpenAI нет.

## Эндпоинты конструктора и совместимости

Методы и полезная нагрузка сохранены. Для записей аккаунтов сервер проверяет
сессию и владение; `owner_token` / `team_token` относятся к прежним записям.

| Метод | Путь | Действие |
| --- | --- | --- |
| `POST` | `/api/analyze` | Анализ черновика и уточняющие вопросы |
| `POST` | `/api/build-card` | Сборка редактируемой карточки из текста и ответов |
| `POST` | `/api/rating` | Расчёт рейтинга без сохранения |
| `POST` | `/api/tasks` | Публикация карточки; ответ содержит `data.task` и `data.owner_token` |
| `GET` | `/api/tasks` | Весь опубликованный каталог: `industry`, `level`, `sort=rating` или `sort=date` |
| `GET` | `/api/tasks/{task_id}` | Публичная карточка задачи |
| `PUT` | `/api/tasks/{task_id}` | Изменение и пересчёт рейтинга с `X-Sana-Owner` |
| `GET` | `/api/teams` | Публичные профили команд |
| `POST` | `/api/teams` | Создание профиля из `name`, массивов `interests`, `skills`, `technologies`; ответ содержит `data.team` и `data.team_token` |
| `POST` | `/api/tasks/{task_id}/proposals` | Предложение с `team_id`, `idea`, `plan`, `deadline`, `link` и `X-Sana-Team` |
| `GET` | `/api/tasks/{task_id}/proposals` | Предложения владельцу задачи с `X-Sana-Owner` |
| `GET` | `/api/teams/{team_id}/proposals` | Предложения своей команды с `X-Sana-Team` |
| `POST` | `/api/proposals/{proposal_id}/decision` | Ручное `accepted` или `rejected` с `X-Sana-Owner` |
| `POST` | `/api/proposals/{proposal_id}/progress` | `result`, `evidence_link` с `X-Sana-Team` после принятия предложения |
| `GET` | `/api/proposals/{proposal_id}/progress` | Отчёты этапов для владельца задачи или соответствующей команды |
| `POST` | `/api/progress/{progress_id}/decision` | Ручное `confirmed` или `rejected` с `X-Sana-Owner` |
| `GET` | `/api/progress` | Табло команд по подтверждённым очкам |
| `GET` | `/api/recommendations?team_id=...` | Дополнительная сортировка задач по совпадению интересов команды |
| `GET` | `/api/health` | Проверка сервера |

Каталог по умолчанию сортируется по убыванию `rating.score`; равные баллы сохраняют порядок добавления. `sort=date` показывает новые задачи первыми. Фильтры не скрывают задачи вне выбранного запроса из общего каталога. Задачи с рейтингом 0–39 тоже видны и принимают предложения.

## Расширение: аккаунты и сдача решений

По прямому запросу владельца проекта первоначальный MVP расширен регистрацией,
командами и ручной проверкой решений. Структура карточки, формула рейтинга и старые
маршруты не заменены. Новые маршруты находятся в `app/account_routes.py`, правила —
в `core/accounts.py` и `core/workflow.py`.

- `POST /api/auth/register`: `name`, `email`, `password` (10–128 символов),
  `role=business|student`; `POST /api/auth/login`: email/password.
- `POST /api/auth/logout` отзывает текущую сессию.
- `GET /api/auth/me`: `user`, `teams` (только свои, с участниками и кодом),
  `owned_task_ids`. Без сессии `user=null`.
- `PUT /api/account/profile`: `name`, `company`, `about`; роль и email неизменяемы.
- `POST /api/account/claim-legacy`: один раз привязывает созданные до появления
  аккаунтов задачи и команды к текущему пользователю. Доступ подтверждается
  прежними секретными токенами из localStorage; без корректного токена запись
  не меняется. Бизнес может восстановить только задачи, студент — только команды.
- `POST /api/account/teams/{id}/invite`: капитан создаёт/заменяет шестизначный
  код на 7 дней. `POST /api/account/join`: `code`; присоединение студента.
- `GET /api/workspaces`: принятые предложения текущего бизнеса/команды, карточки,
  сообщения наставника и история решений.
- `POST /api/workspaces/{proposal_id}/submit`: `result`, `link`, `comment`.
  Только команда выбранного предложения. Версии нумеруются атомарно; новая версия
  допустима после возврата, не во время проверки и не после принятия.
- `POST /api/workspaces/{proposal_id}/review`: `version`,
  `decision=accepted|returned`, `comment`; комментарий обязателен при возврате.
  Только владелец задачи. Старые версии сохраняются. Автоматической оценки нет.
- `POST /api/workspaces/{proposal_id}/coach`: `question`; возвращает историю
  `messages`. AI-наставник использует OpenAI и только факты карточки, не выполняет
  задание вместо команды. При отсутствии ключа или ошибке API возвращается
  безопасный план с `source=fallback`.
- `GET /api/notifications`: события предложений/решений; `POST
  /api/notifications/read`: `ids`. Интерфейс проверяет события каждые 15 секунд.

Новые ответы сохраняют `{ok,data}` / `{ok:false,error}`; ошибки новых маршрутов
используют HTTP 400/401/403. Cookie `sana_session`: случайный непрозрачный токен,
HttpOnly, SameSite=Strict, Secure при HTTPS, 7 дней. В хранилище только SHA-256
токена и salted PBKDF2-SHA256 пароля (600000 итераций). Записывающие запросы
требуют `X-Sana-Request: 1` и same-origin. Авторизация проверяется сервером.

Каталог и отдельная карточка остаются публичными. Рекомендации отображаются
как подсказка и больше не меняют выбранную сортировку рейтинга. Аккаунт бизнеса
связан с `owner_id`, команда — с `creator_id` и участниками. Старые записи и
bearer-токены не удаляются; они не дают доступа к новым аккаунтным записям.
Автоматического присвоения старых задач новому аккаунту нет.

`workflow.json` (или запись `workflow/accounts` в существующем PostgreSQL)
хранит аккаунты, сессии, участников, приглашения, сообщения, версии и прочтения.
JSON использует существующие файловые блокировки; PostgreSQL — транзакционную
advisory-блокировку. Это компактное MVP-хранилище, не новая БД.
`SANA_LEGACY_MODE=1` допускается только для прежних тестов/локальных демо,
по умолчанию 0. Не включать на публичном сайте.

Ограничения этой версии: нет подтверждения email и восстановления пароля;
проверки выполнялись с JSON, PostgreSQL требует отдельного интеграционного прогона;
помощник рабочего пространства и AI-конструктор используют модель при доступном
провайдере и явно помеченный резервный режим при его отсутствии. Для публичной эксплуатации нужен HTTPS и постоянное
хранилище. Тестовые учётные записи не входят в репозиторий.

`core/store.py` работает с JSON в `.sana-data/`; это рабочая папка по умолчанию, она исключена из Git. `SANA_DATA_DIR` меняет её путь. Файлы в `data/` — отдельные синтетические примеры кейса для тестов и сверки, не стартовый контент реального каталога. `.env.example` содержит названия переменных без секретов. Полная инструкция запуска и повторяемый пользовательский сценарий находятся в корневом `README.md`.

## Расширение: AI for SME & Local Business

Бизнес-помощник расширяет входной сценарий для предпринимателей Тараза и
Жамбылской области. Диагностика и библиотека сценариев доступны без аккаунта;
они не создают задачи, не публикуют карточки и не меняют рабочее хранилище.
Переход в конструктор передаёт черновик, который пользователь проверяет и
публикует через существующий процесс после входа как предприниматель.

### Отрасли и цели

`industry`: `cafe`, `retail`, `beauty`, `service`, `agriculture`, `tourism`.
`goal`: `revenue` (выручка), `costs` (расходы), `time` (время).
Новые интерфейсы используют эти значения; прежние строки отраслей в существующих
задачах сохраняются, миграция старых карточек не выполняется.

### Публичная диагностика

`POST /api/business/diagnose` принимает JSON-объект до 24 KiB:

```json
{
  "business_name": "Демо: кофейня в Таразе",
  "city": "Тараз",
  "industry": "cafe",
  "goal": "time",
  "challenge": "Демонстрационный пример: администратор вручную переносит заказы из сообщений в таблицу и хочет сократить время обработки.",
  "locale": "ru"
}
```

| Поле | Проверка |
| --- | --- |
| `business_name` | Строка, 2–160 символов после обрезки пробелов |
| `city` | Строка, 1–120 символов |
| `industry` | Один из шести идентификаторов выше |
| `goal` | `revenue`, `costs` или `time` |
| `challenge` | Строка, 20–4000 символов после обрезки пробелов |
| `locale` | `ru` или `kk`; по умолчанию `ru` |

Заголовок `X-Sana-Request: 1` и same-origin проверка сохраняются и для публичного
POST. Сессия не требуется. Ошибка входных данных возвращает HTTP 400 и
`{"ok":false,"error":{"code":"invalid_input","message":"..."}}`.
Ошибки защиты запроса возвращают HTTP 403. JSON-ответы сохраняют общую обёртку
`{"ok":true,"data":{...}}`.

Успешный `data` содержит:

| Поле | Структура и смысл |
| --- | --- |
| `source` | `fallback` — правила без модели; `openai` — модель участвовала в приоритизации |
| `summary` | Строка: введённый контекст и явно предложенная гипотеза, без гарантии эффекта |
| `opportunities` | Три объекта `{title,description,metric,kpi,first_step,effort}`; все поля строки, `kpi` повторяет `metric` |
| `plan` | Четыре объекта `{week,title,actions}`; `week` 1–4, `title` строка, `actions` массив строк |
| `questions` | Массив из 3–5 строк с вопросами перед внедрением |
| `task_draft` | Строка с введёнными бизнесом, городом, целью и описанием ситуации |

Модель только определяет порядок проверенных отраслевых сценариев и выбирает
вопросы из заданного набора. Свободный текст модели не превращается в факты
или финансовые обещания. При отсутствии провайдера, `AI_MODE=fallback`, ошибке
или некорректном ответе используется детерминированный порядок по выбранной цели.

Четыре недели — предложенный план пилота, а не установленный пользователем срок.
`task_draft` не получает из рекомендаций неподтверждённые сроки, бюджет или
результаты. Если подписи и контекст вместе превысят лимит конструктора в 4000
символов, возвращается весь исходный `challenge` без обрезки. Перенос черновика
не является его публикацией. Запрос диагностики
не сохраняется в серверное хранилище; при включённой модели описанный контекст
передаётся AI-провайдеру для приоритизации.

### Библиотека сценариев

`GET /api/business/templates?locale=ru` возвращает:

```json
{
  "ok": true,
  "data": {
    "templates": [
      {
        "id": "cafe",
        "industry": "cafe",
        "title": "Кафе: гости возвращаются",
        "problem": "Пример ситуации для редактирования пользователем",
        "description": "Описание предлагаемого сценария",
        "kpi": "Показатель для проверки",
        "steps": ["Первый шаг", "Второй шаг", "Третий шаг"]
      }
    ]
  }
}
```

Ответ содержит шесть шаблонов, по одному на отрасль; `id` совпадает с `industry`.
Все поля текстовые, кроме `steps` (массив строк). Пример выше показывает структуру,
не полный ответ. `locale` принимает `ru` или `kk`, по умолчанию `ru`; неверный язык
возвращает HTTP 400. Шаблоны не являются задачами каталога или свидетельствами
работы с реальными клиентами.

### Локальный план и калькулятор

Калькулятор и сравнение пилота работают в браузере без отдельного API.
Формулы описаны в [соответствии треку](TRACK_ALIGNMENT.md). По кнопке «Сохранить»
ключ `sana.business.workspace.v1` получает JSON с `version:1`, `saved_at`,
`profile`, `assumptions`, `pilot`, `diagnostic`, `result_profile`.
`profile` соответствует полям запроса диагностики; `result_profile` фиксирует
контекст последней диагностики отдельно от текущей редактируемой формы.

`assumptions`: `monthly_revenue`, `monthly_costs`, `gross_margin_pct`,
`hours_per_week`, `hourly_cost`, `revenue_growth_pct`, `cost_reduction_pct`,
`automation_pct`, `setup_cost`, `monthly_tool_cost`. Все значения неотрицательные;
проценты 0–100, часы в неделю 0–168, стоимость часа до 100 000 000, остальные
денежные значения до 1 000 000 000 000. Значения формы могут сохраняться строками;
при восстановлении они проверяются и преобразуются в числа.

`pilot`: `metric`, `unit`, `direction` (`higher`/`lower`), `baseline`, `target`,
`actual`. Сравнение использует значения, введённые пользователем; оно не доказывает
причину изменения. При нулевой базе процент изменения не рассчитывается.

Экспорт плана — отдельный JSON с `title`, `version`, `exported_at`, `profile`,
`diagnostic`, `diagnostic_profile`, `forecast: {assumptions,result,disclaimer}`,
`pilot`, `storage`. Сохранение не синхронизируется с аккаунтом; восстановление
читает только текущий браузер. Импорт экспортированного JSON не реализован.

### Анализ продаж CSV в браузере

Для CSV-анализа нет серверного маршрута: файл разбирается в браузере и не
отправляется в FastAPI или AI-провайдеру. `parseSalesCsv(text)` принимает UTF-8
текст до 1 MiB и 10 000 строк продаж, допускает BOM, разделитель `,` или `;`,
экранированные кавычки и заголовки в любом порядке. Обязательные уникальные
колонки: `date`, `product`, `quantity`, `price`, `cost`.

`date` — существующая дата `YYYY-MM-DD`; `product` — непустая строка до
160 символов; `quantity`, `price`, `cost` — числа от 0 до 100 000 000.
`price` и `cost` задаются на одну единицу. Поддерживаются дробные значения,
пробелы в числах и десятичная запятая в соответствующем CSV-поле.
Отрицательные возвраты и экспоненциальная запись не поддерживаются.
Неполные строки, повторные заголовки и повреждённые кавычки отклоняются.

`analyzeSales(records, from, to)` включает обе границы периода и возвращает
`revenue`, `costs`, `profit`, `margin`, `quantity`, `rows`, `products`, `timeline`,
`alerts`, `periodStart`, `periodEnd`. В продукте: `name`, `quantity`, `revenue`,
`costs`, `profit`, `margin`, `share`; в дне: `date`, `revenue`, `costs`.
Маржа при нулевой выручке равна `null`, отрицательная прибыль не обнуляется.
Пустой выбранный период не генерирует рекомендации.

`alerts` содержит `{tone,title,text,metric}` по детерминированным правилам:
отрицательная прибыль продукта, маржа от 0% включительно до 20% исключительно,
доля одного продукта более 60%, предложение повторять проверку для непустых данных.
Пороги диагностические, не отраслевые нормы. Эти подсказки не используют модель.
Скачивание демонстрационного CSV и отчёта происходит в браузере.
