# AGENTS.md

Инструкции для AI-агентов, работающих в этом репозитории.

## Проект

**Sana Business AI** — сервис для малого и среднего бизнеса Тараза и Жамбылской
области в треке **AI for SME & Local Business**. Он помогает предпринимателю
выбрать процесс для улучшения, оценить возможный эффект и подготовить задачу
для внедрения. Основные цели: рост выручки, снижение затрат и автоматизация рутины.

Публичный CSV-анализ продаж, диагностика и калькулятор — вход в продукт. Следующий шаг — существующий
AI-конструктор: бизнес вводит черновик, отвечает минимум на три уточняющих вопроса,
проверяет редактируемую карточку и вручную публикует её. Команды предлагают решения,
бизнес выбирает исполнителей и принимает результат. Рейтинг 0–100 описывает полноту
задачи; подтверждённые баллы команды отражают отдельную механику прогресса.

## Правила предметной области

1. **AI не выдумывает факты.** В карточку попадает только то, что пользователь
   сообщил. Неизвестные поля остаются пустыми. Примеры и рекомендации не становятся
   фактами бизнеса без подтверждения.
2. **Человек подтверждает.** Карточка редактируется и публикуется только вручную.
   Диагностика не публикует задачи и не создаёт заказов.
3. **Команду выбирает бизнес.** Система показывает предложения и действия
   «Выбрать» / «Отклонить», не назначает исполнителя автоматически.
4. **Низкий рейтинг ничего не скрывает.** Любая опубликованная задача видна
   в каталоге и принимает отклики. Рейтинг влияет на позицию и метку.
5. **Рейтинг прозрачен.** Показываем разбивку и сведения, которых не хватает.
6. **Число откликов не ограничено.** Любая команда может откликнуться на задачу.
7. **Экономический эффект — сценарий, а не обещание.** Формулы используют только
   ввод пользователя; предположения помечаются. Высвобождённые часы нельзя незаметно
   прибавлять к денежной прибыли. Результат пилота требует реального измерения.
8. **Демо не выдаётся за клиентов.** `data/` содержит синтетические фикстуры.
   Не подмешивать их в рабочий каталог и не утверждать, что ими доказан эффект.

## Стек и границы модулей

- Python 3.11+, FastAPI, Uvicorn.
- React 19 + Vite; production-сборка — `app/static/`.
- `core/store.py`: JSON в `.sana-data/` или существующий PostgreSQL через `DATABASE_URL`.
- `core/ai.py`, `core/prompts.py`: AI-конструктор и помощник команды.
- `core/business.py`: шаблоны и диагностика бизнеса.
- `core/rating.py`: чистая детерминированная формула рейтинга.
- `core/accounts.py`, `core/workflow.py`, `app/account_routes.py`: аккаунты,
  состав команд, версии решений и ручная приёмка.
- `app/main.py`: маршруты и серверные проверки доступа.
- `frontend/src/salesAnalytics.js`, `frontend/src/SalesAnalytics.jsx`: CSV-анализ
  в браузере без отправки файла на сервер; подсказки детерминированы.
- `frontend/src/BusinessWorkspace.jsx`: диагностика, калькулятор, локальный план.
- `tests/`: проверки; `docs/CONTRACT.md`: структуры данных и API.

Сохранять границы: `app/` вызывает публичные функции `core/`; рейтинг не обращается
к сети и файлам. Не добавлять новую БД, Docker, real-time или новые интеграции
без необходимости. Аккаунты, уведомления и работа команд уже существуют;
сохранять их вместо возврата к устаревшему режиму без регистрации.

## Контракт и совместимость

Менять структуры и API только с обоснованием и обновлением `docs/CONTRACT.md`.
Внутренняя роль участника команды остаётся `student` для совместимости;
пользовательский интерфейс может называть её «участник команды».
Старые bearer-токены не дают доступ к новым аккаунтным записям.
`SANA_LEGACY_MODE=1` предназначен только для прежних тестов/локального демо.
На рабочем сайте оставлять `0`.

## Запуск и проверка

Из корня репозитория, PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
npm ci
npm run build
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Повторно не перезаписывать существующий `.env`. В другом терминале:

```powershell
.\.venv\Scripts\python.exe -m pytest -q
node --test tests/salesAnalytics.test.mjs
```

## Секреты и качество кода

- Ключи только в `.env`, исключённом из Git. В `.env.example` — имена переменных
  и несекретные значения по умолчанию. Не помещать секреты в код, тесты, промпты,
  документацию или логи.
- Ясные имена, без «умных» однострочников. Не рефакторить посторонние модули.
- Каждый внешний API-вызов — с таймаутом и обработкой ошибок.
- Проверять тип, пустые значения, допустимые диапазоны и длину входных данных.
- При недоступном AI возвращать детерминированный резервный результат с явным
  `source: "fallback"`; не выдавать его за ответ модели.
- Не обходить серверную авторизацию, same-origin проверки и подтверждение человека.
- Не коммитить `.env`, `.venv/`, `.sana-data/`, `__pycache__/` или реальные бизнес-данные.

## Перед коммитом

1. Выполнить подходящие проверки, включая `pytest -q` и сборку изменённого фронтенда.
2. Проверить запуск сервера и изменённый пользовательский сценарий.
3. Убедиться, что в diff нет секретов, рабочих данных и случайных локальных путей.
4. Новые зависимости фиксировать в соответствующем манифесте, новые переменные —
   в `.env.example`.
5. Использовать префиксы `feat:`, `fix:`, `test:`, `docs:` или `chore:`.
